# Sync v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace timestamp-merged deck sync with a server-ordered operation log plus on-demand collection snapshot.

**Architecture:** `anki_core` owns `Op`, `Collection` (pure, idempotent reducer, derived FSRS scheduling) and the wire protocol. The server dedupes ops by id, numbers them with a per-user counter and materializes rows. The client keeps `base` (server state @ seq) + durable `outbox`; `view = base + outbox`; all writes go through one serialized `CollectionStore`.

**Tech Stack:** Dart 3.13, Flutter, Riverpod 3, shelf, postgres 3, fsrs 2.0.1, uuid 4.

**Spec:** `docs/sync-v2-design.md`

## Global Constraints

- No clock value participates in conflict resolution or pending detection.
- Every op is idempotent under `Collection.apply`.
- Op ids: UUIDv4 from the client; review id == op id; v1 review id = `v1:<cardId>@<reviewedAt ISO-8601 UTC as Dart prints it>`.
- `SyncPush.maxOps = 500`, `SyncPull.pageSize = 2000`.
- Seed ids: `Uuid().v5(Namespace.url.value, 'poormans-anki/seed/<deck>')` and `.../seed/<deck>/<front>`.
- Client files: `collection/base.json`, `collection/outbox.jsonl`, `collection/state.json`. v1 files (`decks/*.json`, `reviews.jsonl`) are read once for migration and left untouched.
- No commits to remote. Comments only per CLAUDE.md (no comments in function bodies).

## Review Focus

1. App killed between `base.json` and `outbox.jsonl` writes → acked ops resent, server dedupes, no duplicate review — `collection_store_test: crash between base and outbox write`.
2. Device offline for a long time while history is compacted → 410 → snapshot → pending outbox survives — `convergence_test`, `sync_service_test: cursor expired`.
3. Two devices first-enable sync with locally seeded decks → one copy — `sync_service_test: seeding converges`.
4. Device clocks skewed by hours → both reviews count, scheduling identical on both — `sync_service_test: clock skew`.
5. User edits while a pull is being applied → edit survives — `sync_service_test: mutation during sync`.
